# 公務員キャリアシフト診断 SNS投稿ジェネレーター

X / Threads 向けの投稿を、下記テンプレ7型と変数バンクから生成する。目的は「流入の再現性」＝当たった型を反復すること。デフォルトは **10本**（指定があればその本数）。

## 出力ルール（必ず守る）

- **フック公式**：各投稿は次の3条件を満たす。①数字 or 固有名詞で始める ②断定しない（素地／可能性／〜できます の表現）③公務員だけが反応する語を入れる（庁内調整・起案・査定・財政課・決裁・予算執行・条例・住民対応 など）。
- **かぎ括弧「」での強調は禁止**（AI創作感が出る）。強調は改行・【】ラベル・語順・箇条書きで表現する。引用符 " " も使わない。
- **煽らない・上から目線にしない**。「公務員はダメ」的な不安煽りは禁止。翻訳＝可能性の提示に徹する。
- **人間らしい文体・締め方**：機械的な定型句の反復は禁止。特に「診断はプロフィールから👇」だけで毎回締めるのは不可——読み手に語りかけるような、丁寧で親しみやすい一言に変える（例：「気になったら覗いてみてください」「自分の場合はどうなるか、のぞいてみませんか」「プロフィールに置いてあります」等、投稿ごとに言い回しを変える）。👇は使っても良いが必須ではなく、地の文で自然に着地させる投稿も混ぜる。
- **改行はコピペ即使用できる形で、多めに・ゆとりを持たせる**：出力時点で、1〜2文ごとに空行（改行を2つ）を入れる。Threadsは特に、意味のまとまりごとに1行の空きを作り、詰まった印象にしない。文中の「/」区切りのような省略表記のまま出力しない——必ず改行込みの完成形で書く。
- **各投稿の締め**：診断への導線を、上記の人間らしい言い回しで自然に置く。リンクは基本プロフィール前提（本文にURLを入れる場合は `https://koumuin-shift.com/`、計測時は末尾に `?utm_source=x` 等を付ける）。
- **重複回避**：同じ変数・同じ言い回しを連投しない。毎回、語尾・語順・具体語・締めの言い回しを変える。X は140字前後、Threads は少し長めの体験談調に。
- **プラットフォーム振り分け**：出力時に各投稿へ `[X]` か `[Threads]` を付ける。柱1・2・5・6は X 向き、柱3・4・7は Threads 向き（共感・長文）。同じネタを X=要点／Threads=物語 に言い換えて出すのも可。
- 出力は**そのままコピペできるプレーンテキスト**。番号と `[X]/[Threads]` ラベル、本文（改行込み・空行入り）、の順で並べる。装飾マークダウン（見出し記号や強調記号）は本文には付けない。

## テンプレ7型（[変数]を差し替えて生成）

以下は「意味のまとまり」を `/` で示した設計図。実際の出力では `/` の位置で改行＋空行を入れ、詰まった印象にしない（Threadsは特に空行を積極的に使う）。締めの一文は例のまま使い回さず、毎回言い換える。

**柱1：翻訳ネタ（主力）**
- T1 単一変換：`[公務員経験]は、民間だと[民間スキル]の素地として活かせます。/ [別の変換1行]。/ 民間で通用しない、はたいてい思い込みです。/ [人間らしい締め＋診断への導線]`
- T2 変換リスト：`【公務員経験 → 民間スキル 翻訳表】/ ・[from]→[to] ×3〜5行 / 断定はできませんが、活かせる素地は確実にあります。/ [人間らしい締め]`

**柱2：職種紹介**
- T5 職種解説：`公務員から狙いやすい職種 [職種]。/ [その職種で評価される力＝公務員経験と接続]。/ [庁内調整/起案 等]の経験がそのまま武器になります。/ [人間らしい締め]`
- T6 ルート提示：`公務員からIT、いきなり未経験エンジニアにならなくて大丈夫。/ ① 公務員（[経験]）→ ② [横移動先職種]へ → ③ IT企業で実務 → ④ [上位職] / [人間らしい締め]`

**柱3：共感／あるある（Threads向き）**
- T3 あるある：`公務員あるある / ・[あるある1] / ・[あるある2] / ・[あるある3] / このしんどい経験、民間だと立派なスキルに翻訳できます。/ [人間らしい締め]`
- T4 心理に刺す：`公務員だから民間で通用しない——この思い込みが一番もったいない。/ [未経験でも効く力の例]。/ 辞める・辞めないの前に、まず翻訳から。/ [人間らしい締め]`

**柱4：不安への回答（Threads向き）**
- T7 Q&A：`Q. [公務員の不安]/ A. [経験を実績として翻訳して見せる]。/ 経験を翻訳すれば[書ける/狙える]。/ [人間らしい締め]`

### 「人間らしい締め」の言い換えバリエーション（ローテーションして使う）
気になったら覗いてみてください／自分の場合はどうなるか、のぞいてみませんか／プロフィールに置いてあります／よかったら試してみてください／プロフィールから見にきてください／興味があれば覗いてみてください／気になった方はプロフィールから／良ければ見てみてください　等。同じ投稿パックの中で同じ締めを繰り返さない。

## 変数バンク

**部署／担当領域**：税務・徴収／福祉・保健・子育て／総務・人事／企画・政策・広報／財政・会計・契約／建設・都市計画／産業振興・観光／教育・文化／住民窓口・戸籍／防災・危機管理／情報システム

**職種（横移動先）**：PMO・プロジェクト推進／BizOps・業務企画／業務改善・DX推進／カスタマーサクセス・導入支援／ITサポート・ヘルプデスク／社内SE補助・情シス／オペレーション・業務自動化

**変換ペア（from → to）**：庁内の部署間調整→ステークホルダー調整／起案・決裁→企画・要件定義／予算要求・執行→プロジェクト予算管理／制度改正対応→業務改善・プロセス設計／住民・事業者対応→顧客折衝・CS／計画策定→企画・戦略立案／補助金事務→オペレーション品質／データ集計→データ活用／広報・周知→情報発信

**公務員あるある**：起案が決裁で3往復／査定で財政課に詰められる／前例は？が口癖／議会答弁の想定問答づくり／年度末の予算消化／異動で全く違う分野へ／窓口対応と内部調整の板挟み

**不安（Q素材）**：民間しか経験がなくて職務経歴書が書けない／プログラミング未経験でIT/Webは無理／営業経験ゼロで通用するか／30代未経験は遅い／自分の実績を数字で語れない

## 生成手順

1. 指定本数を、柱1・2を多め（主力）にしつつ4つの柱から配分する。
2. 各投稿に変数を割り当て（部署・職種・変換ペア・あるある等をローテーションし、重複させない）。
3. フック公式と出力ルールを満たす本文を書く。かぎ括弧「」・引用符は使わない。
4. 本文は**意味のまとまりごとに空行を入れた完成形**で書く（コピペしてそのまま投稿画面に貼れる状態。「/」のような区切り記号を本文中に残さない）。締めの一文は「人間らしい締め」の言い換えバリエーションから、投稿パック内で重複しないよう選ぶ。
5. `[X]`／`[Threads]` を付け、番号順にプレーンテキストで出力。
6. 最後に「予約投稿メモ」：1日3〜5本・時間分散・同一文の連投は避ける、を1行添える。

## シリーズモード：「今日の翻訳」

「今日の翻訳を作って」「翻訳シリーズを◯本」などで起動する特別モード。柱1（T1/T2）をベースに、**通し番号つきの定型フォーマット**で毎回1つの変換ペアだけを扱う。目的は「診断を受けなくても単体で消費・シェアされる、認識可能なシリーズ資産」を作ること。

- フォーマット（固定）：
  ```
  今日の翻訳 #[N]

  [公務員経験（from）]

  ↓

  [民間スキル（to）]

  [1〜2行の補足。断定しない／素地・可能性の表現]

  無料診断で、あなたの経験も翻訳できます👇
  ```
- 通し番号 `#[N]` は前回からの続き番号。ユーザーに直近の番号を確認し、不明なら `#1` から開始する。
- 変換ペアは「変数バンク」の組み合わせに limitせず、既存の翻訳表（`lib/results.ts` の `skillTranslations`）からも引用してよい。ただし文言はそのまま複製せず言い換える。
- 通常の10本パック生成と混在させる場合は、シリーズ投稿には冒頭に `[X][シリーズ#N]` のようにラベルを付けて区別する。
- OGカードの仕組み（`/api/og`）と組み合わせて画像化する場合は、「今日の翻訳」の1枚カード化を別途検討する旨を出力の最後に一言添える（実装は別タスク）。

## 予約投稿（コストゼロ運用）

生成後、Claude in Chrome で X の標準予約投稿（Web版コンポーザー）／Threads のネイティブ予約 or Meta Business Suite に、生成文を貼り付けて予約登録する。API課金なし。1回あたり10〜20件をまとめて登録し、キューが減ったら再生成→補充する。
